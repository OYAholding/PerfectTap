## 2. Security finding for the economy session (pre-existing, not introduced here)

**QA-01 (High):** `private.purchase_economy_item` grants the item even when
`apply_economy_delta` reports a duplicate `event_key` (no charge). Re-sending an old event key with
a *different* `p_item_id` grants that item for free. Reproduced in a throwaway Postgres container:
`docs/cosmetics/qa/sql/purchase_item_duplicate_event_key.test.sql` (test 6 fails on purpose).
Suggested fix: when the delta result is `duplicate`, return it without calling
`set_profile_item`, or bind `event_key` to `item_id` in the ledger. Please confirm whether
`20261127110000_economy_hardening.sql` (only in the release worktree) already covers this.
The proposed bundle RPC in this branch does not have the bug.

# PerfectTap! — דוח שחזור, ביקורת ומודרניזציה (נובמבר 2026)

סימון: **[אומת]** = נקרא בקוד / הורץ בפועל. **[הסקה]** = מסקנה שדורשת בדיקה במכשיר / בקונסולה.

## 1. זהות המשחק
- משחק תזמון בלחיצה אחת: מחוון זוהר נע הלוך-חזור על פס, ולוחצים כשהוא במרכז. PERFECT / GREAT / GOOD / MISS, קומבו שמכפיל ניקוד, ומהירות שעולה.
- **ההיסטוריה (שוחזרה מהקבצים):**
  - מרץ 2026: גרסת ווב ב-Base44 (React/Vite). היא נשארה ב-`src/` וב-`perfect-tap.zip`.
  - מרץ–אפריל 2026: פורט לאפליקציית iOS נייטיב ב-SwiftUI, עם Firebase (Auth אנונימי, Firestore), AdMob ו-StoreKit 2.
  - העדכון האחרון לקבצים: 14 באפריל 2026. גרסה 1.0.2, Bundle ID `com.perfecttap.app`.
- **התוכן:** 15 מצבים (Classic, Endless, Timed, Sudden Death, Combo Frenzy, Zen, Precision, Chaos, Mirror, Invisible Zone, Rush, Hardcore Combo, Tiny Window, Focus, Duel).
- **מערכות התקדמות:** XP ורמות, Season Pass, 21 הישגים, משימות יומיות, פרסי התחברות, גלגל מזל, אתגרים, חנות ערכות נושא, חברים, לוח מובילים ודו-קרבות.

## 3. ארכיטקטורה
- **מבנה:** SwiftUI + MVVM קל. `AppRouter` מנהל את ה-NavigationStack. `GameViewModel` מריץ לולאת CADisplayLink ב-60fps, ו-`IndicatorRelay` גורם לכך שרק הפס מתרנדר בכל פריים, וזה פתרון טוב.
- **פרופיל:** local-first ב-UserDefaults, עם שיקוף ל-`players/{uid}`.
- **הפרויקט עצמו:** נוצר מ-XcodeGen (`project.yml`). הגדרות שנעשו ידנית ב-Xcode (צוות חתימה, גרסה 1.0.2, קטגוריה) לא היו ב-yml. הוספתי אותן כדי ש-`xcodegen generate` לא ימחק אותן.
- **האם הייתי בוחר אותו stack היום?** כן: SwiftUI + Firebase מתאימים למשחק כזה. לא צריך שכתוב. כדאי בהמשך:
  - לעבור ל-`@Observable` (iOS 17) כשתעלו את מינימום ה-iOS.
  - לשקול `ProMotion 120Hz` למחוון חלק יותר.
  - להעביר את כל ההרשאות על כסף ותוצאות לשרת.

## 6. הזדמנויות מודרניזציה
- **תזמון:**
  - כיול השהיית תצוגה לכל מכשיר (קבוע `displayLatencyFrames`).
  - 120Hz במכשירי ProMotion.
  - משוב "מוקדם / מאוחר" (early/late) ליד PERFECT, ששומר על זהות המשחק ועוזר לשחקן להשתפר.
- **הוגנות ותחרות:** Cloud Function v2 לאימות תוצאות וכלכלה, כללי Firestore עם רשימת שדות מותרים, ואם תרצו גם App Check.
- **UX:**
  - ספירה לאחור קצרה אחרי revive או חזרה מרקע.
  - נגישות בסיסית.
  - Haptic מסונכרן לרגע הפגיעה (כבר קיים `perfectHit` שלא בשימוש).
- **AI (רק היכן שזה זול ומועיל):**
  - בפיתוח: בדיקות אוטומטיות ו-playtesting סימולטיבי (בוט שמשחק בכל מצב ובודק עקומת קושי).
  - בשחקן: לא מומלץ להוסיף AI בזמן ריצה. אין לזה ערך מול העלות.

## 8. מה בוצע בפועל (ענף `recovery/modernization-2026-11`)

1. **קלט touch-down עם חותמת זמן חומרה**
   - קבצים: `Components/TouchDownTapArea.swift` (חדש), `GameView.swift`, `GameViewModel.swift`.
   - הניקוד מחושב לפי המיקום שהשחקן ראה ברגע המגע: זמן הנגיעה פחות פריים אחד, באקסטרפולציה מהפריים האחרון.
   - נשמרו label ונגישות של כפתור "TAP!", כך שה-UI test ו-VoiceOver ממשיכים לעבוד.
2. **החזרת חלונות הפגיעה לגודל המצויר ולגרסה המקורית (±4% / ±10% / ±20% מרוחב הפס)**
   - קובץ חדש: `Utils/TimingEngine.swift`.
   - ⚠️ **המשחק נעשה סלחני יותר מגרסת ה-iOS האחרונה.** אם רוצים להחזיר את הקושי, עדיף לכווץ גם את הציור וגם את הלוגיקה יחד ב-`GameConfig`.
3. **החזרה מקיר עם שמירת עודף התנועה** במקום "הדבקה" לקיר בפריים ארוך.
4. **משוב על כל לחיצה** (מונה `tapSequence`).
5. **שחזור פרופיל מהענן בהתקנה מחדש** (`AuthViewModel.swift`).
